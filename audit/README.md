# Audit Module

This optional Module has its own Go-module version in the existing repository. `Version()` and `Descriptor.Version` report the actual packaged Audit dependency; Core has a separate identity. [Consumption](../docs/architecture/consumption-and-packaging.md) owns compatible dependency selection and the transition from monolithic releases. The legacy `ModuleVersion` constant is retained only as a deprecated unpublished source-line label, not component/update/recovery identity; `achrix.audit.append`, `achrix.audit.query` and `achrix.audit.export` use ABI 1 and require Core authorization ABI 2. Release-specific history belongs to the [lifecycle guide](../docs/lifecycle/lifecycle-and-compatibility.md).

Products explicitly install `audit.Migrate(ctx, dsn)` with a deadline before startup, then compose `audit.NewPostgres(dsn, audit.Config{Now: clock}, logger)` and construct `audit.NewService(app, module)`. Runtime startup verifies the exact immutable migration ledger and enabled mutation guards; it does not migrate. This baseline uses the [supported PostgreSQL profile](../docs/operations/operability-performance.md#supported-environment) with UTF-8, transactional DDL, native transactions and advisory locks, without extensions. Installation and runtime DSN sources, database roles and secrets remain product-owned.

Identity is the real proving domain. Successful account provision, credential replacement, self password change, account status transition and revoke-all are **atomic-required**: Identity authorizes its domain capability, Audit `Prepare` authorizes append on the same stable account target, then Identity changes its owned state and calls `audit.AppendInTx` within that one native PostgreSQL transaction. Audit owns its SQL; Identity never writes Audit tables. Any append error requires rollback of the entire domain transaction. A successful append return is not commit proof. A lost commit acknowledgement is unavailable, not permission to replay a mutation; the domain owns its revision/reconciliation behavior.

`Event` carries only bounded action, stable target, owning authority capability and the `succeeded` outcome. Audit derives actor from the authorized principal, generates the opaque record ID and captures the injected UTC time at microsecond precision. Authority metadata describes the domain contract; it grants no permission. The caller must pass opaque actor/target references and domain classification names, never credentials, password hashes, session secrets, display text or request bodies. Audit has no arbitrary payload field. Successful ordinary login, session rotation/logout and repetitive denied/invalid attempts remain outside the retained dataset; operational diagnostics own those concerns.

`Prepared` is opaque, single-use and bound to its originating live context/deadline and Module. A fresh context cannot revive a canceled preparation. `AppendInTx` tracks and cancels its owned SQL during Module stop while the caller retains transaction/commit ownership. The consumer must drain its transaction work before Audit stops; Identity declares that dependency. `CheckDatabase` compares normalized connection credentials, database, runtime/TLS/protocol and fallback settings without exposing them, rejecting ambiguous driver callback settings conservatively. Remote primary **and every fallback** require certificate-verified TLS with hostname verification. Unix/loopback plaintext is the local development profile, not a remote deployment support claim. Driver environment/service/password/certificate resolution remains trusted product configuration, not public request input.

Query and export have separate target-specific permissions and limits of 1–100 records per call. Cursors use an internal sequence and are bound to the target; every page reauthorizes. Each page reads committed visible records. Pages are not one consistent snapshot across requests, and concurrent insert transactions can become visible out of sequence. For a complete consistent export/recovery operation, quiesce accountable domain writes or use the product's supported database snapshot/backup profile. The baseline retains all records and provides no deletion, mutation or invented retention/legal policy. Corrections/redaction need a separately accepted domain/product requirement.

The owned schema rejects record UPDATE, DELETE and TRUNCATE with database triggers and constrains identifiers/metadata. This is append-oriented application integrity, **not cryptographic tamper evidence**: privileged database operators can change/drop the guards or schema. Startup and explicit installation checks verify guard presence; readiness only pings the database; they are not continuous privileged-tampering detection. Restore must preserve the entire owned `audit` schema, records, sequence, immutable migration ledger and trigger functions, together with the coupled Identity/account state. Source rollback does not reverse retained state. Whole-product/off-host/RPO/RTO support remains downstream of the real product recovery work.

`Config.MaxConns` bounds the instance pool (zero defaults to four; explicit minimum one). `Config.MaxOperations` bounds active owned leases (zero defaults to 16; explicit minimum two), with fail-fast admission and no lease queue. Standalone `Append` holds its transaction lease plus the nested `AppendInTx` lease; the minimum supports an isolated append, without promising fairness for concurrent nested work. `AppendInTx` may use a caller-owned connection, so lease and connection budgets differ. Public calls require deadlines. Pool minima remain zero, with one minute idle/health period, one hour lifetime without jitter and one second connect/ping limits. Typed pool/admission settings are not database identity and do not change `CheckDatabase` or explicit `Migrate` profiles. [Operations](../docs/operations/operability-performance.md#module-resource-configuration) owns aggregate budgets and native demand-based behavior. Operational failures preserve safe public identities and produce phase-aware diagnostics under the contract below. Repeated denied/invalid/capacity traffic creates neither Audit records nor provider-error logs.

`ACHRIX_AUDIT_TEST_DSN` must identify the separate task-owned validation database with the `achrix_audit_` name prefix; tests preflight that guard before explicitly resetting only its Audit schema. Identity tests use a different database and install both owned schemas to prove the real same-transaction consumer. The shared validation script additionally owns normal pinned consumption and retained-dataset restore proof.

## Actionable errors and protected diagnostics

`*InputError` identifies a malformed actor, target, action, authority, outcome, limit or cursor without echoing caller values; `errors.Is(err, ErrInput)` remains supported. A cursor does not prove permission. Exact target authorization, immutable records and the atomic append contract remain unchanged.

`Config.Diagnostic` optionally receives `(ctx, operation, phase, originalCause)` synchronously before ordinary-log suppression. Keep the same trusted request/operation context. This is a protected product-owned boundary: raw provider errors may contain secrets/data, so apply provider-aware targeted redaction before restricted storage/export, keep diagnostics outside public serving, bound retention/volume and return promptly. Do not pass raw causes to an ordinary logger. Normal `slog` records retain safe source-owned explanations, typed cause, validated SQLSTATE/network reason, phase and relevant outcome. Local process/file diagnosis requires no collector. [Operations](../docs/operations/operability-performance.md#diagnosis-and-audit) owns the common handling policy.

`MigrateWithDiagnostics(ctx, dsn, logger, diagnostic)` adds that boundary to explicit installation. Existing `Migrate(ctx, dsn)` delegates using the default logger. Startup and migration identify environment, ledger cardinality/version/checksum, runtime columns, missing/disabled mutation guards, lock, DDL, ledger write, commit and cleanup failures. Diagnose and fix the named precondition; do not rewrite immutable migration history. Useful technical facts are retained while arbitrary SQL/driver messages remain protected.

A live-caller dependency timeout/cancellation is operationally diagnosed; a normal caller-aborted read is distinct. Transaction diagnostics distinguish pre-begin `not_executed`, `not_committed`, uncertain commit `unknown`, and acknowledged `committed`. A SQLSTATE indicating statement/transaction resolution uncertainty is not rollback proof. `AppendInTx` owns the original append cause; the committing domain may add its distinct transaction outcome. Cleanup failure never overwrites the primary result; harmless `pgx.ErrTxClosed` is ignored. None of these categories grants blanket retry permission.

The ordinary one-second diagnostic window retains 56 distinct ordinary signatures and reserves eight for unknown mutation outcomes. Its private bounded fingerprint retains no raw cause text and explicitly marks truncated fingerprints with original length in safe metadata. One timer emits repeated counts and overflow even when traffic stops, and shutdown flushes pending summaries. `diagnostic_summary=true` records use no individual request context; counts are aggregate evidence, not attribution to a single caller. The protected callback still sees every operational cause and owns its own repetition/storage policy. Product handlers preserve these final summaries. This is bounded troubleshooting evidence, separate from durable Audit and from abuse controls.
