# Development Roadmap

This is the **durable outcome sequence**, not a task/status report. The [Master Specification](../MASTER-SPEC.md) owns success criteria, the [Module model](../architecture/module-model.md) owns reusable placement, and GitHub Issues/PRs/CI/releases own current execution, gates and evidence.

1. **Keep a usable, versioned Foundation.** Preserve the minimal Core/Application authorization boundary and normal, independently pinned Core/Module consumption. Each real consumer must be able to compose and intentionally upgrade compatible versions without copying Foundation internals. The first executable [baseline #1](https://github.com/AChWorks/achrix/issues/1) and [Core hardening #44](https://github.com/AChWorks/achrix/issues/44) retain their historical proof; new behavior follows [Contracts](../architecture/contracts-and-interfaces.md), [Consumption](../architecture/consumption-and-packaging.md) and [Lifecycle](../lifecycle/lifecycle-and-compatibility.md).

2. **Build reusable behavior from real products.** Extend an existing Module where ownership fits, and implement a new shared capability only with actual consumer/evidence needs. [Multi-Site #4](https://github.com/AChWorks/achrix/issues/4) is a consumer-proof reference; [Search #48](https://github.com/AChWorks/achrix/issues/48), [Settings #50](https://github.com/AChWorks/achrix/issues/50) and [Notifications #110](https://github.com/AChWorks/achrix/issues/110) own their respective activation requirements. [Bridge client integration #5](https://github.com/AChWorks/achrix/issues/5), [optional OAuth/OIDC issuer #125](https://github.com/AChWorks/achrix/issues/125) and [Media picker #126](https://github.com/AChWorks/achrix/issues/126) have distinct ownership and acceptance; reusable placement alone does not ship a feature. [Rixa #49](https://github.com/AChWorks/rixa/issues/49) and [Gateway #86](https://github.com/AChWorks/mcp-gateway/issues/86) own their product-side integration work.

3. **Prove real product lifecycle and recovery.** A product should provide understandable authorized installation/update, compatible artifact activation, migration, backup/restore and actionable diagnosis without routine user-run server commands. [First-product lifecycle proof #19](https://github.com/AChWorks/achrix/issues/19) owns the product/deployment acceptance gate; [reusable Backup & Recovery #49](https://github.com/AChWorks/achrix/issues/49) depends on that proof. Neither this roadmap nor an architectural boundary activates owner-gated work or authorizes a generic host/root/updater service.

4. **Validate broader reuse before extracting more infrastructure.** Compare at least one materially different real consumer, refine shared semantics and support profiles when evidence differs, and extract another service/repository/provider only if its ownership, security, workload or lifetime economics justify it. Avoid speculative registries, marketplaces, empty Modules and premature multi-service designs.
